## 2. Practical Tips and Experiences for Responsible AI Usage

AI is a cognitive accelerator, not an autonomous replacement for human judgment. Misusing AI can introduce hallucinations, subtle algorithmic bugs, and severe security flaws. Based on my hands-on experience, I adhere to the following principles:

### Tip 1: Treat AI as a "Junior Developer" — Always Verify and Test
* **Observation:** LLMs are statistical sequence generators that prioritize plausibility over factual correctness. They frequently fabricate non-existent API parameters or propose algorithms with hidden boundary edge-case failures.
* **Strategy:** Never accept generated code without verification. Every AI-suggested function must be subjected to manual line-by-line inspection, static analysis, and **deterministic unit tests** before integration.

### Tip 2: Decouple Natural Language from Algorithmic Logic
* **Observation:** Relying on an LLM to perform complex mathematical calculations or execute graph traversals (such as Dijkstra's algorithm) leads to unpredictable and non-deterministic behavior.
* **Strategy:** Respect the principle of separation in Computational Thinking:
  - Use AI strictly for **perceptual and linguistic tasks** (e.g., parsing fuzzy user queries into structured JSON schemas).
  - Delegate all state updates, mathematical computations, and constraint checks to **deterministic, testable code** (e.g., Python/C++ algorithms).

### Tip 3: Maintain Strict Data Hygiene and Credential Security
* **Observation:** Cloud-based AI platforms may log user interactions, exposing proprietary source code, internal network addresses, or environment keys if pasted recklessly.
* **Strategy:** Enforce strict sanitization before submitting prompts:
  - Strip all private API keys, database credentials, server IP addresses, and personal identifiable information (PII).
  - Use synthetic schemas, mock JSON payloads, and anonymized variable names when requesting architectural feedback.

### Tip 4: Utilize Structured, Constrained Prompting
* **Observation:** Ambiguous prompts produce vague, superficial output that requires heavy rewriting.
* **Strategy:** Supply explicit schemas, domain boundaries, and negative constraints:
  - Define input/output contracts (e.g., *"Return output strictly as a JSON object adhering to the provided Pydantic model"*).
  - Explicitly restrict undesirable behavior (e.g., *"Do not introduce external dependencies; implement the solution using standard library data structures"*).

### Tip 5: Retain Intellectual Ownership and Explainability
* **Observation:** Presenting code generated by AI that you cannot personally defend or explain leads to failure during code reviews, project defenses, and grading evaluations.
* **Strategy:** If I cannot explain why an algorithm was chosen, its time complexity ($O(V \log V + E)$), its memory footprint, and its primary failure modes without consulting the AI tool, the code is **not ready for production**. The ultimate responsibility for system behavior rests entirely on the engineer, not the assistant.
